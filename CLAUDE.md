# Лаборатория нестабильных порталов — контекст проекта

Тестовое задание на вакансию AI-first Developer в MOX, вариант «Лаборатория
нестабильных порталов».

**Срок по заданию — до 5 дней** (с возможностью согласовать продление до 10).
В первой редакции этого файла стояло «2–3 дня» — это была ошибка, сверено
с оригиналом задания.

- Живая версия: https://spisusha.github.io/portal-lab/
- Репозиторий: https://github.com/spisusha/portal-lab
- Текущий релиз: https://github.com/spisusha/portal-lab/releases/tag/v1.1.0 —
  версия 1.1 «Живая смена». Ветка `feature/live-shifts-v1.1` слита в `main`
  обычным merge и больше не ведётся; работать нужно от `main`.
  Предыдущий релиз — v1.0.0 (коммит `772e154`).
- Pages публикуется только из `main`, автоматически при push.
- Исходное задание: https://mox-studio.notion.site/AI-first-Developer-MOX-38894a5391e18140a0edf7192f03723c

Страница задания в Notion собирается скриптами: обычная загрузка вернёт
пустой шаблон. Текст достаётся через публичный API
(`POST https://www.notion.so/api/v3/loadPageChunk`), причём вторая половина
страницы лежит в отдельном чанке — нужен второй запрос с курсором из первого.

## Перед началом работы

1. Прочитать `docs/PLAN.md` — чеклист статуса и метка «остановились здесь».
2. Прочитать `docs/worklog.md` — там честная история решений и ошибок.
3. Посмотреть `git log --oneline -15`.
4. Не переделывать то, что уже отмечено галочкой.

## Команды

| Команда | Что делает |
|---|---|
| `npm install` | установка зависимостей |
| `npm run dev` | локальный запуск на `/portal-lab/` |
| `npm test` | все тесты: домен + интеграционные UI |
| `npm run build` | `tsc -b` + сборка в `dist/` |

## Стек

Vite 6 + React 19 + TypeScript + Vitest 3. UI-тесты — Testing Library
поверх jsdom. Деплой — GitHub Pages через `.github/workflows/deploy.yml`
при push в `main`.

Важно: **vitest и vite должны оставаться совместимыми по мажору.** Связка
vite 6 + vitest 2 ломает сборку: npm кладёт vitest собственную вложенную
копию vite 5, и в проекте оказывается два несовместимых типа `Plugin`.

  rules.ts       запреты с причинами, двухшаговое закрытие, stabilizePower

  forecast.ts    прогноз «Через цикл» вместе с событием живой смены
  reducer.ts     переходы состояний, цикл времени, схлопывание

  focus.ts       «что требует решения сейчас» + причина выбора
  plural.ts      русские числительные (нужны и домену, и интерфейсу)
  seed.ts        три набора демо-данных + вход в живую смену
  live/          всё, что относится только к режиму «Живая смена»
    prng.ts        детерминированный PRNG от строки seed (xmur3 + mulberry32)
    seedCode.ts    формат кода PL-XXXX и приведение к каноническому виду
    url.ts         разбор и сборка ?mode=live&seed=… с учётом base path
    worlds.ts      по одной особенности на каждый из девяти миров

  liveSeed.ts    адаптер: crypto.getRandomValues, window.location, буфер обмена

  worldArt.ts    силуэты девяти миров в виде путей SVG
  WorldScene.tsx сцена мира и мелкий знак для строки списка

## Правила, которые нельзя нарушать

- **Ни одной формулы и ни одного запрета внутри компонентов.** Расчёт риска —
  в `domain/risk.ts`, запреты — в `domain/rules.ts`, выбор срочного портала
  и текст причины — в `domain/focus.ts`. Компоненты только показывают то,
  что вернул домен.
- **Никакого реального времени в домене.** `Date.now`, `setInterval` и
  `performance.now` внутри `src/domain` запрещены. Живая смена идёт в реальном
  времени (15 лабораторных минут за 60 секунд), но весь таймер — в
  `src/state/liveClock.tsx`, а домен получает ту же команду `NEXT_CYCLE`, что
  и кнопка «Следующий цикл» учебного сценария. Второй реализации перехода нет,
  поэтому прогноз не может разойтись с фактом.
- **Никакой неуправляемой случайности в домене.** `Math.random` и `Date.now`
  внутри `src/domain` запрещены — иначе сценарии перестанут быть
  воспроизводимыми и тесты поплывут. Детерминированная генерация по seed
  разрешена и используется режимом «Живая смена»: собственный PRNG лежит в
  `domain/live/prng.ts`, а строку seed домен получает снаружи уже готовой.
  Единственное место с настоящей случайностью — адаптер
  `src/state/liveSeed.ts` (`crypto.getRandomValues`).
- **Запрет объясняется до нажатия.** Кнопка недоступного действия —
  `disabled`, причина из `checkAction` выводится рядом. Никаких `alert`
  после клика.
- **Учебные сценарии неприкосновенны.** `standard`, `critical` и
  `empty` остаются полностью детерминированными и служат проверкой
  обязательных состояний задания. Механики живой смены к ним не
  применяются: признак `Portal.trait` у их порталов пуст, `LabState.live`
  равен `null`, и все формулы работают ровно как в версии 1.0.
- **Опасность никогда не кодируется одним цветом.** Ранг дублируется буквой,
  словом и формой — залитыми сегментами кольца в `PortalRing`. Это требование
  доступности, а не украшение.
- **Вся графика своя.** В `public/assets/portals` лежат оригинальные
  ImageGen-ассеты девяти миров, сделанные для этого проекта; остальное
  (кольцо портала, силуэты, знаки действий, зерно фона) нарисовано кодом.
  Сторонних изображений, внешних шрифтов и CDN в проекте нет и быть не
  должно — и из-за офлайн-работы, и из-за чужих прав. Во время работы
  приложение ничего не загружает: ассеты собираются в бандл, путь к ним
  строится из `import.meta.env.BASE_URL`, а не зашивается строкой.
- **Любая анимация выключается** через `prefers-reduced-motion` — правило
  уже есть в конце `theme.css`, новые анимации обязаны под него попадать.
- **Worklog ведётся по ходу.** Как только AI ошибся или предложил неудачное
  решение — сразу строка в `docs/worklog.md`. Задним числом это не
  восстановить, а честность здесь прямо оценивается.
- **Секретов в проекте нет** — внешние API не используются.

## Как проверять работу

Тесты и сборка обязательны, но их мало: половина ошибок этого проекта была
видна только глазами. Полезные приёмы, уже опробованные:

- **Тесты живого времени идут на поддельных таймерах** и подделывают только
  `setInterval`, `clearInterval` и `Date`. Полная подмена (`vi.useFakeTimers()`
  без `toFake`) ломает Testing Library: её асинхронная обёртка ждёт настоящий
  `setTimeout`, который под поддельными часами никто не крутит, и любой
  `user.click` виснет до таймаута теста.
- **Правила адаптива для новых блоков пишутся после базовых.** Общий раздел
  «Адаптив» в `theme.css` стоит выше секции «Живая смена», поэтому при равной
  специфичности медиазапрос оттуда проигрывает базовому правилу и молча не
  действует. Проверяется только глазами.
- **Телефон проверяется отдельно, а не «уменьшением десктопа».** Камера
  портала на 390 px выше экрана целиком, поэтому подсказка вступления там
  физически не может встать «рядом» с подсветкой — только листом сверху или
  снизу. Логика выбора стороны живёт в `cardPosition` (`Onboarding.tsx`)
  и считает свободное место, а не середину подсветки.
- **Прогон живого приложения через CDP.** В Node 24 есть встроенный
  WebSocket, поэтому браузером можно управлять без зависимостей: запустить
  Chrome с `--remote-debugging-port`, подключиться к `/json/list`, слать
  `Runtime.evaluate` и `Page.captureScreenshot`. Так проверяются сценарии,
  ошибки консоли и переполнение по ширине.
- **Ширину окна headless Chrome нельзя опустить ниже ~485 px.** Для проверки
  360/390 px нужен iframe фиксированной ширины внутри широкого окна, иначе
  скриншот просто кадрируется и выглядит «сломанным», хотя вёрстка цела.
- **Переполнение меряется, а не оценивается на глаз**:
  `document.documentElement.scrollWidth` против `clientWidth`.
