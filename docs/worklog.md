# AI Worklog — финальная версия

Рабочие заметки, которые ведутся по ходу дела. Готовая версия для проверяющего
живёт в приложении: `src/ui/WorklogScreen.tsx`, вкладка «AI Worklog».
Этот файл — источник, экран — витрина.

## Сводка перед сдачей

- [x] Общее время разработки: около 9–10 часов (оценка пользователя)
- [x] Инструменты перечислены честно
- [x] Точная статистика токенов не отслеживалась: использованные инструменты не предоставили единого общего счётчика
- [x] Формулировки перечитаны и не приписывают пользователю ручное написание кода или ручные проверки

## День 1

### Инструменты

Claude Code (модель Opus 5) внутри оболочки mirasim. Других AI не использовал.

### Что происходило

**Уточнение ТЗ.** Страница задания на Notion собирается скриптами, поэтому
обычная загрузка вернула пустой шаблон, и AI поспешно заключил, что задания
нет. Пришлось указать, что так не пойдёт — со второй попытки текст вытащили
через публичный API Notion (`loadPageChunk`), включая вторую половину страницы,
которая лежала в отдельном чанке.

**Разбор терминов.** Перед началом попросил объяснить, зачем нужен README,
что такое edge cases и почему AI Worklog требуют встроить в интерфейс.

**Проблема контекста между сессиями.** Отдельно разобрали, как не терять
прогресс при переходе в новый чат. Решение: `CLAUDE.md` (читается автоматически)
+ `docs/PLAN.md` (чеклист статуса) + осмысленные коммиты. Это пригодилось в тот
же день — сессию пришлось перезапускать, и план поднялся из файла без
пересказа.

**План.** Утверждён до написания кода: разбивка по блокам, формула риска,
таблица запретов, архитектура с чистым доменом.

**Домен.** Написан целиком: типы, риск с разбором на слагаемые, правила,
редьюсер, рекомендации, сводка, три набора демо-данных. Числа в демо-данных
подобраны под заранее известные ранги, чтобы на них могли опираться тесты.

**Интерфейс.** Сводка, список, карточка, журнал, подтверждение, демо-сценарии,
вкладка worklog. Оформление своё, без картинок и внешних шрифтов.

### Ошибки AI за день

1. **Сдался на первой попытке прочитать ТЗ** — решил, что страница пустая.
2. **Использовал тип `ActionCheck` в `rules.ts`, не объявив его** в `types.ts`.
   Сборка бы упала.
3. **Битые символы в исходниках**: иероглиф в комментарии `seed.ts`, обрывки
   слов в `summary.ts` и `ConfirmDialog.tsx`, и `#2b4known` вместо цвета в
   CSS-переменной. Последнее особенно неприятно — такое не ловится типами.
4. **Предлагал живой таймер** вместо ручного цикла.

### Что изменено после проверки пользователя

Код в перечисленных пунктах менял AI; пользователь указывал, какое поведение
нужно исправить, и проверял результат.

- Живой таймер → кнопка «Следующий цикл».
- Объявление `ActionCheck`, чистка битых символов.
- Наблюдатель отчитывается через цикл, а не мгновенно — иначе правило
  «наблюдатель уже внутри» недостижимо, а предупреждение о закрытии портала
  с наблюдателем внутри было бы мёртвым кодом.
- Естественный дрейф параметров за цикл: без него бездействие ничего не стоило.

### Чем закончился день

Весь код написан, но **ни разу не собран и не запущен**: команды установки
в сессии блокировались. Тесты и браузерная проверка — первое дело следующей
сессии.

## День 2

### Первая сборка

Установка наконец прошла. Домен оказался в порядке: 24 теста из 24 зелёные
с первого запуска, в логике не пришлось править ни строки. А вот сборка
упала дважды, и оба раза — на конфиге, который день 1 написал вслепую.

### Ошибки AI за день

5. **`/// <reference types="vitest/config" />` не работает.** Поле `test`
   в `vite.config.ts` типизируется только если `defineConfig` импортирован
   из `vitest/config`, а не из `vite`. Тройная ссылка аугментацию не
   подтянула — `tsc` упал на TS2769.
6. **Несовместимые версии в `package.json`.** Поставили vite 6 и vitest 2.1
   вместе, а vitest 2.1 знает только про vite 5. npm молча положил vitest
   его собственную вложенную копию vite 5 — в проекте стало два разных типа
   `Plugin`, и сборка развалилась простынёй на 25 строк про
   несовместимость `PluginOption` с самим собой. Диагноз не читается
   из текста ошибки: видно только два пути в `node_modules`, и надо
   догадаться посмотреть на вложенный `node_modules/vitest/node_modules`.
   Лечится подъёмом vitest до 3.x. Попутно ушли 3 из 5 уязвимостей.

Общая мораль дня: **код, который никогда не запускался, ломается не в логике,
а в стыках инструментов.** Тесты домена, написанные вслепую, прошли идеально;
падало ровно то, что нельзя проверить чтением, — разрешение версий.

### Что проверил

- `npm test` — 24/24.
- `npm run build` — `tsc -b` по всему UI + бандл 264 kB.
- Дерево компонентов отрендерил разово через `react-dom/server`: ни одной
  runtime-ошибки. Временный файл проверки удалил, чтобы не мусорить.
- `npm run preview` — продакшн-сборка отдаётся по `/portal-lab/`, ассеты 200.
  Значит `base` для Pages выставлен верно.
- Прогнал исходники на битые символы (день 1 их уже ловил) — чисто.

### Переоформление: «видно, что делала нейронка»

Главное замечание дня — моё, не AI. Открыл интерфейс и сразу увидел то,
что не заметил, пока читал код: типовой AI-шный «космический HUD».
Разобрали по пунктам, что именно выдаёт машину:

- **уголки-скобки** по краям панелей — самый частый штамп;
- **свечение на всём сразу**: заголовок, вкладки, ранги, счётчики, диалог.
  Когда светится всё, иерархии нет;
- **моноширинный шрифт для всего текста**, включая русскую прозу;
- **CAPS и разрядка на каждой подписи** — восемь разных мест;
- **шесть цветов рангов** вразнобой, хотя ранг — одна ось, опасность;
- **рамка вокруг каждого элемента** вместо группировки фоном и воздухом.

Новое направление — измерительный прибор, а не игровой HUD: темно, но
спокойно. Моноширинный оставлен только там, где содержимое целиком
числовое; ранги выстроены в одну монотонную шкалу от серого к красному;
свечение убрано полностью, единственная тень — у модального окна, где она
означает «лежит выше»; появилась шкала отступов и видимый фокус
с клавиатуры. Логика не тронута: правка только в `theme.css` плюс два
инлайновых стиля, переехавших из разметки в таблицу стилей.

Свою же первую версию переоформления пришлось поправить дважды: сначала
я объявил правило «моноширинный только для чисел», а применил его целыми
блоками — и проза в строках вроде «Итоговый риск» превратилась в листинг.
И названия порталов во фразе «требуют внимания» остались кнопками-чипсами,
которые рвали предложение на коробочки. Обе ошибки было видно только
на скриншоте, не в коде.

### Ложная тревога с узким экраном

Отдельный урок про доверие к собственным глазам. Снял скриншот на 430 px,
увидел обрезанные справа колонки и починил «переполнение»: добавил мобильную
раскладку. Потом решил измерить, а не смотреть, — и оказалось, что
переполнения не было: headless-браузер не открывает окно уже ~485 px и
просто кадрировал картинку по запрошенной ширине. Померил по-честному,
через iframe шириной 375 px: `scrollWidth` совпадает с шириной окна,
список переполняющих элементов пуст.

Мобильная раскладка в итоге осталась — на 360 px она объективно лучше
трёхколоночной строки, — но поставлена она по измерению, а не по
показалось. Диагностический скрипт и пробную страницу убрал.

### Публикация

GitHub CLI поставился через `winget`, вход — через браузер с одноразовым
кодом. Почта в профиле скрыта, поэтому в `git config` поставили
GitHub-овский noreply-адрес: история коммитов не должна раскрывать личную
почту. Настройка сделана локальной для репозитория, а не глобальной.

Первый деплой упал, и причина поучительная: `gh repo create --push`
отправил код раньше, чем я успел включить Pages, а `actions/configure-pages`
падает с «Not Found», если Pages ещё не настроен. Порядок должен быть
обратный — сначала включить Pages в режиме `workflow`, потом пушить.
Перезапуск того же прогона прошёл успешно.

## День 3 — редизайн ради понятности

### С чего начался

Диагноз мой: логика работает, тесты зелёные, ссылка открывается — а человек,
впервые открывший приложение, не понимает, кто он, какова цель и что нажимать
первым. Требования к переделке я готовил отдельно, с помощью ChatGPT/Codex:
прогнал по ним аудит интерфейса и собрал список того, что должно измениться.
Claude Code получил уже готовое ТЗ на редизайн.

### Что оказалось не так при разборе

AI перечитал исходное задание и прошёл живое приложение браузером. Нашлось
четыре конкретные причины непонятности:

1. Первым на экране стоял переключатель **демо-сценариев** — служебный
   инструмент разработчика выше цели работы.
2. **Рекомендация лежала примерно на 1100-м пикселе прокрутки**, ниже разбора
   формулы: человеку сначала показывали арифметику и только потом — что делать.
3. Про роль и цель не было сказано **нигде**: слова «не допустить схлопывания»
   в интерфейсе не встречались.
4. Шкала рангов E–S работала **без легенды**, и опасность передавалась
   только цветом.

Заодно всплыло расхождение с исходным ТЗ: срок там **5 дней**, а не 2–3,
как было записано в `CLAUDE.md`.

Здесь же — ещё одна ошибка AI, показательная. Он заявил, что в worklog
**нет ключевых промптов**, хотя требование ТЗ про них есть. На деле промпты
были с самого начала: в компоненте `Stage` поле называется `prompt`
по-английски, а AI искал по русскому слову «промпт» и, не найдя, сделал
вывод об отсутствии. Проверка поиском по одному написанию — плохое
основание для вывода «этого нет».

### Решения, которые принял я

AI задал пять вопросов по дизайну с вариантами. Мои ответы:

- **Вступление** — гибрид: модалка из трёх шагов при первом входе плюс
  постоянная полоса с целью, которая никуда не девается.
- **Живой портал** — не герой во весь экран, а кольцо внутри блока
  «Требует решения сейчас», плюс мелкие знаки миров в списке.
- **Палитра** — «чернила и нефрит»: важно, чтобы человек нормально видел.
- **Демо-сценарии** — максимально практично, то есть в шапку.
- **Ассеты миров** — тут я честно не знал, что лучше, и сказал: главное,
  чтобы было красиво. Решение принял AI — девять авторских SVG-сцен вместо
  растровых картинок: предсказуемое качество, ничего не надо генерировать
  отдельно и нет риска задеть чужие права.

### Ошибки AI за день

7. **Снова битый цвет в CSS.** В новой палитре появилось значение
   `--jade-deep: #10archived` — ровно тот же класс ошибки, что `#2b4known`
   в день 1. Не ловится ни типами, ни сборкой: CSS просто молча игнорирует
   мусорную переменную. Нашлось перечитыванием файла.
8. **Сцены миров показывали пустое небо.** У SVG стояло
   `preserveAspectRatio="xMidYMid slice"`, а полоса сцены сильно шире своих
   пропорций — кадр обрезался по центру, и вся земля с силуэтами оставалась
   за краем. Выглядело как «AI нарисовал пустоту». Лечится прижатием кадра
   к низу: `xMidYMax`. Видно было только на скриншоте.
9. **Пустая колонка в пол-экрана.** После перестройки иерархии журнал уехал
   на всю ширину вниз, а карточка справа оказалась втрое длиннее списка —
   слева зияла дыра. Решено сеткой именованных областей: в разметке порядок
   остался приоритетным (список → карточка → журнал), а визуально журнал
   встал под список.

Первые две ошибки объединяет одно: **их не видно в коде и не ловит ни один
тест.** Оба раза помог взгляд на картинку.

### Как проверялось

- 49 тестов: 37 доменных и 12 интеграционных на интерфейс (Testing Library
  поверх jsdom) — вступление, главная кнопка решения, запрет при ранге S,
  подтверждение закрытия, ход времени, пустая смена, клавиатура и Escape.
- Живое приложение пройдено браузером через CDP: все сценарии, ошибок
  в консоли нет.
- Контраст посчитан для 23 пар цветов — все не ниже 4.5:1.
- Ширины 360 / 390 / 768 / 1280: `scrollWidth` равен `clientWidth`,
  горизонтальной прокрутки нет.

## Финальная переделка интерфейса

После развёрнутого аудита интерфейс перестроен вокруг одной центральной камеры
портала. Дублирующие блоки «Требует решения сейчас» и полная карточка слиты;
очередь сортируется по опасности; четыре действия показывают последствия и
причины запрета; до цикла виден прогноз, после действия — разница состояния.
Формула, история и журнал сохранены в раскрывающихся панелях.

AI Worklog получил ограниченную ширину чтения, содержание, краткую сводку,
структурированные этапы и раскрывающиеся технические подробности. Формулировки
о «ручном коде пользователя» убраны: код меняли AI-агенты по решениям и после
проверки пользователя.

Финальную реализацию начали в Claude Code и завершили в Codex после
переключения агента. Браузерный прогон через доступный Chrome DevTools MCP проверил онбординг, выбор портала,
стабилизацию, запрет и последующее разрешение разведки, отчёт наблюдателя,
метку «под вопросом», отмену и подтверждение закрытия, три демо-сценария,
Worklog, клавиатуру и размеры 1440×900, 768×1024, 390×844. Ошибок консоли и
горизонтального переполнения не обнаружено. `npm test` — 71/71, production
build прошёл.

Время разработки заполнено со слов пользователя. Единого общего счётчика
токенов по нескольким сессиям не было, поэтому в отчёте оставлена точная
оговорка вместо выдуманной цифры.

## Финальный этап — завершённость продукта

Пользователь попросил довести демо до конечной смены: убрать возможность
повторять решения в одном цикле, сделать активную очередь единственным
источником числа открытых порталов и показать реальный итог смотрителя.

AI добавил в доменную модель номер цикла принятого решения, время отметки,
счётчики стабилизации, возвратов наблюдателей и потерь существ. После каждого
успешного решения кнопки этого портала блокируются с объяснением; следующий
цикл сбрасывает отметку только у всё ещё активных порталов. Закрытые и
схлопнувшиеся порталы больше не попадают в очередь, но остаются в журнале и
итогах. Переход к циклу с нерешёнными порталами подтверждается отдельно.

Смена теперь заканчивается после шести циклов по 15 минут или досрочно, когда
активных порталов не остаётся. Финальный экран считает длительность, циклы,
исходное и оставшееся количество порталов, стабилизации, закрытия,
схлопывания, критические и «под вопросом» состояния, наблюдателей, безопасных
и опасных существ, потери и общее число решений. Оценка выбирается только по
правилам задания: «Отличная смена», «Смена под контролем» или «Смена с
потерями».

### Проверка финального этапа

- `npm ci` — выполнено после остановки оставшихся dev/preview-процессов; 2 умеренные npm advisory, не используемые приложением.
- `npm test` — 71/71 тест, включая 16 новых проверок конечной смены и очереди.
- `npm run build` — успешно.
- Browser fallback: CLI `agent-browser` в окружении отсутствовал, поэтому для визуальной проверки использован доступный Chrome DevTools MCP/локальный production preview.

### Возможные улучшения реального продукта

Сохранение смены между перезагрузками, серверная история смен, настройка весов
формулы, скринридерный аудит и генерация новых порталов во время настоящего
дежурства остаются осознанными следующими шагами. Они не нужны для этой
конечной демонстрационной смены и поэтому не добавлялись.
